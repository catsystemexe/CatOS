# ChatGPT handoff – 2026-07-12 Human Gate

## 1. Session metadata

- **Datum:** 2026-07-12
- **Aktuální branch:** aktuální pracovní branch v repozitáři CatOS.
- **Výchozí stav:** CatOS pipeline již uměla dokončit Task Analyst → Codex Worker → Validation Runner → Reviewer → bounded Rework Loop a uložit `final-result.json`, ale po finálním výsledku neexistoval deterministický lidský auditní bod.
- **Cíl kroku:** přidat první verzi immutable Human Gate po `final-result.json`, bez commitů, pushů, PR, LLM volání, Codex reworku nebo změn cílového worktree.
- **Doporučený commit:** `feat: add immutable human approval gate`

## 2. Executive summary

Byla přidána deterministická komponenta Human Gate a CLI příkaz `decide`, který nad dokončeným runem načte a validuje `final-result.json`, ověří klíčové artefakty a jednorázově uloží `runs/<runId>/human-decision.json`. Podporovaná rozhodnutí jsou `APPROVE`, `REJECT` a `REQUEST_CHANGES`.

`APPROVE` je záměrně povoleno pouze pro finální stav `ACCEPTED` a vyžaduje potvrzení všech evidence položek. `REQUEST_CHANGES` vyžaduje alespoň jednu konkrétní změnu. Druhé rozhodnutí nad stejným runem je odmítnuto.

## 3. Změny provedené v tomto kroku

### `src/schemas/humanDecision.ts`

- Přidáno verzované Zod schema `humanDecisionSchema` se `schemaVersion: 1`.
- Přidána cross-field pravidla přes refinement:
  - `APPROVE` pouze pro `finalResultStatus === "ACCEPTED"`.
  - `APPROVE` vyžaduje všechny `evidenceReviewed` hodnoty `true`.
  - `REQUEST_CHANGES` vyžaduje neprázdné `requestedChanges`.

### `src/humanGate.ts`

- Přidáno úzké rozhraní `HumanGate` a implementace `FileHumanGate`.
- `FileHumanGate.recordDecision` ověřuje shodu `runId`, existenci povinných artefaktů a jednorázově zapisuje `human-decision.json` přes `flag: "wx"`.
- Human Gate nemění cílový worktree a nepoužívá LLM ani Codex.

### `src/cli/decide.ts` a `src/index.ts`

- Přidán CLI příkaz `npm run catos -- decide --run <runId> --decision <approve|reject|request-changes>`.
- Parser podporuje opakované `--change` a opakované `--reviewed`.
- Před zapsáním rozhodnutí vypisuje stručný souhrn: objective, final status, validation status, review verdict, changed files, sandbox isolation poznámku, total coding attempts a cesty k diffu/reportům.
- Po uložení rozhodnutí vypisuje stav Human Gate a upozornění, že commit zatím není implementován.

### `src/schemas/finalResult.ts` a `src/cli/run.ts`

- `final-result.json` byl minimálně rozšířen o volitelné cesty k finálnímu diffu a finálnímu validation reportu.
- Nové runy tyto cesty zapisují, aby Human Gate nemusel slepě odhadovat poslední attempt adresář.
- Starší `final-result.json` bez nových polí zůstávají validní; Human Gate má fallback na root artefakty pro zpětnou srozumitelnost.

### `tests/humanGate.test.ts`

- Přidány fixture testy bez OpenAI/Codex API pro Human Gate a CLI parsing.
- Testy pokrývají schválení, odmítnutí nevalidních schválení, reject, request changes, zápis artefaktu, odmítnutí druhého rozhodnutí, chybějící/nevalidní run artefakty, opakované CLI argumenty a neměnnost worktree obsahu.

### `README.md`

- Dokumentována první verze Human Gate, příkaz `decide`, evidence confirmation, `human-decision.json`, jednorázovost rozhodnutí a zákaz commit/push/PR v této etapě.

## 5. Bezpečnostní stav po změně

Zachováno:

- Nebyl přidán commit worker.
- Nebyl přidán push, merge ani GitHub API.
- Human Gate nespouští Codex ani žádné LLM volání.
- `APPROVE` nemá force override pro `HUMAN_REQUIRED` ani `REWORK_LIMIT_REACHED`.
- Existující `human-decision.json` se nepřepisuje.
- `REQUEST_CHANGES` pouze uloží instrukce; automatický rework se nespouští.

## 6. Známá rizika

- Validace nemohla doběhnout kvůli blokovaným dependencies a Node.js 20 v kontejneru.
- `decide` pro sandbox isolation zatím vypisuje odkaz na `coding-result.json`, protože `final-result.json` před touto etapou neobsahoval normalizované pole sandbox isolation.
- Starší runy bez nových cest ve `final-result.json` používají fallback na root artefakty; rework runy vytvořené před touto změnou mohou vyžadovat doplnění cest ručně nebo nové spuštění pipeline.

## 7. Doporučený další krok

V prostředí s Node.js 22+ a dostupnými dependencies spustit `npm ci` nebo `npm install`, poté `npm run typecheck`, `npm run test` a `npm run build`. Následně vytvořit fixture nebo reálný dokončený run a ověřit `npm run catos -- decide` pro `APPROVE`, `REJECT` a `REQUEST_CHANGES`.
