## Objective

Generate per-attempt Markdown reports immediately at terminal Coding, Validation, and Review artifact persistence time, keep terminal timeline reports pointed at Markdown, keep raw JSON as machine-readable evidence, and keep the Final row tied to `final-result.json`.

## Starting defect

Per-attempt Markdown reports were delayed until session/final export. During a live run the timeline could select `coding-result.json`, `validation-report.json`, or `review-report.json` as the user-facing REPORT target before Markdown existed.

## Root cause

`writeCodingArtifacts()`, `writeValidationReport()`, and `writeReviewReport()` persisted JSON but did not render Markdown. `ensureStepResultArtifacts()` in `src/finalExport.ts` contained the per-attempt Markdown rendering, so reports appeared only when `writeSessionReport()`/`writeFinalReport()` ran. `reportCandidates()` in `src/uiViewModel.ts` still allowed raw JSON after Markdown candidates. `writeSessionReport()` was an unconditional alias for `writeFinalReport()`.

## New lifecycle contract

Coding, Validation, and Review source JSON remains authoritative machine-readable evidence. Each terminal source JSON write now immediately attempts to generate the matching human-readable Markdown report in the same artifact scope. Timeline report selection prefers Markdown, then explicit generation-error Markdown, then raw JSON only for legacy/incomplete compatibility.

## Coding report timing

`writeCodingArtifacts()` writes `coding-result.json`, `workspace.diff`, and `workspace-status.txt`, then immediately calls the shared Coding attempt Markdown writer to produce `coding-report.md`.

## Validation report timing

`writeValidationReport()` writes `validation-report.json`, then immediately calls the shared Validation attempt Markdown writer to produce `validation-report.md`, including `SKIPPED` validation results.

## Review report timing

`writeReviewReport()` validates and writes the reconciled `review-report.json`, then immediately calls the shared Review attempt Markdown writer to produce `review-report.md` from the persisted Review result.

## Final report and Final row contract

`writeFinalResult()` still persists `final-result.json` and then refreshes `FINAL_REPORT.md`. `buildUiTimeline()` only appends Final when `final-result.json` exists. `writeSessionReport()` refreshes step artifacts but does not create `final-result.json` and does not fabricate a Final row before terminal final state exists.

## Report failure handling

Report rendering/writing is wrapped narrowly. If Markdown generation fails after source JSON persistence, the source JSON remains on disk and an explicit `*-report-error.md` artifact is attempted so user-facing report selection has a readable failure artifact before JSON fallback.

## Timeline path preference

`reportCandidates()` now orders Coding, Validation, and Review candidates as per-attempt Markdown first, then report-generation error Markdown, then source JSON legacy fallback. Final remains `FINAL_REPORT.md` only when `final-result.json` exists.

## Legacy aggregate compatibility

Legacy aggregate reports `01_CODEX_REPORT.md`, `02_VALIDATION_REPORT.md`, and `03_REVIEW_REPORT.md` remain generated by final/session export for compatibility. Concrete timeline rows use per-attempt Markdown reports and do not depend on aggregate reports.

## Behavior before

Markdown was generated late by final/session export. Live terminal rows could expose raw JSON as REPORT. `writeSessionReport()` called final export even when `final-result.json` did not exist.

## Behavior after

Terminal Coding/Validation/Review persistence immediately creates corresponding Markdown. Timeline report path preference points normal terminal rows at Markdown. Source JSON remains available. `writeSessionReport()` can refresh step reports without inventing Final state.

## Contracts and invariants

- Per-attempt Markdown is generated immediately at each terminal Coding/Validation/Review source JSON write.
- Source JSON remains authoritative machine-readable evidence.
- Terminal UI REPORT defaults to Markdown for normal terminal events.
- Raw JSON is not the normal user-facing report for terminal Coding/Validation/Review.
- Later attempts write their own reports and do not overwrite prior attempt reports.
- Final row requires `final-result.json`.
- `writeSessionReport()` does not invent terminal state.
- Report-generation failures remain explicit and recoverable when possible.
