# ChatGPT handoff – 2026-07-12 Rework loop

## 1. Session metadata

- **Datum:** 2026-07-12
- **Aktuální branch:** aktuální pracovní branch v repozitáři CatOS.
- **Výchozí stav:** CatOS měl funkční tok Task Analyst → Codex Worker → externí Git worktree → Validation Runner → Reviewer → `review-report.json`. Reviewer uměl vrátit `ACCEPT`, `REWORK` nebo `HUMAN_REQUIRED`, ale `REWORK` zatím nespouštěl další Codex iteraci.
- **Cíl kroku:** přidat první ohraničenou verzi rework loopu bez Human Gate, commitů cílového projektu, push/merge, GitHub API, Memory, event logu, Temporal/LangGraph nebo UI.
- **Výsledný commit:** bude vytvořen jako `feat: add bounded Codex rework loop`.

## 2. Executive summary

CatOS nyní po review pokračuje automaticky pouze při `review.verdict === "REWORK"`. Coordinator deterministicky sestaví verzovaný `ReworkPackage`, pokračuje přes `CodingWorker.continueTask()` ve stejném Codex threadu a stejném externím worktree, znovu uloží coding artefakty, spustí Validation Runner a Reviewer a smyčku opakuje nejvýše podle `workflow.maxReworkAttempts`.

Každý rework pokus má vlastní auditní adresář `runs/<runId>/attempts/NN/`. První pokus kvůli kompatibilitě zůstává v root artefaktech runu. Každý běh nově končí souborem `runs/<runId>/final-result.json`.

## 3. Změny provedené v tomto kroku

### `src/schemas/reworkPackage.ts`

- Přidáno Zod schéma `reworkPackageSchema` se `schemaVersion: 1`.
- Schéma obsahuje attempt, původní objective, acceptance criteria, blocking findings, preserve, mustChange, mustNotChange a previousAttemptSummary.

### `src/schemas/finalResult.ts`

- Přidáno Zod schéma `finalResultSchema`.
- Podporované statusy jsou `ACCEPTED`, `HUMAN_REQUIRED` a `REWORK_LIMIT_REACHED`.

### `src/reworkLoop.ts`

- Přidána deterministická konstrukce `ReworkPackage` z TaskBriefu, ReviewReportu, CodingResultu, ValidationReportu, diffu a čísla pokusu.
- `blockingFindings` se berou přímo z ReviewReportu.
- `mustChange` se mapuje z `requiredChange`.
- `mustNotChange` se mapuje z `TaskBrief.nonGoals`.
- Přidána fingerprint detekce opakovaného blocking finding z normalizovaných polí title, evidence a requiredChange.
- Přidány helpery pro zápis `rework-package.json` a `final-result.json`.

### `src/codingWorker.ts`

- Rozšířen kontrakt `CodingWorker` o `continueTask(input: ReworkCodingTask)`.
- Přidán typ `ReworkCodingTask` obsahující `threadId`, `workspacePath`, `reworkPackage` a `sandboxMode`.
- Přidána auditovatelná rework instrukce pro Codex: původní cíl, acceptance criteria, blocking findings, required changes, preserve, must-not-change, stejný worktree, zákaz commit/push/merge a zákaz práce mimo workspace.
- `CodexSdkWorker.continueTask()` používá resume/continue mechanismus Codex klienta (`resumeThread` nebo `continueThread`) a nesmí spustit nový thread.

### `src/cli/run.ts`

- Coordinator nyní řídí bounded rework loop.
- Smyčka běží pouze pro `REWORK`; `ACCEPT` a `HUMAN_REQUIRED` ji ukončují.
- Limit se bere z `workflow.maxReworkAttempts`.
- `REWORK` bez blocking findings se ukončí jako `HUMAN_REQUIRED`.
- Stejný blocking finding ve dvou po sobě jdoucích review ukončí automatiku jako `HUMAN_REQUIRED`.
- Opakovaný validation `BLOCKED` nesmí způsobit nekonečné automatické opakování.
- CLI vypisuje začátek rework pokusu, rework validation, rework review verdict, finální status, počet coding pokusů a cestu k `final-result.json`.

### `tests/runCli.test.ts`

- Aktualizován existující CLI test na nový `final-result.json`.
- Přidány injected testy pro `ACCEPT` bez reworku, `HUMAN_REQUIRED` bez reworku, `REWORK → ACCEPT`, `REWORK → HUMAN_REQUIRED`, vyčerpání limitu, opakovaný blocking finding, `REWORK` bez findings a oddělené artefakty pokusů.
- Fake Coding Worker vrací odlišné výsledky pro první a rework pokusy a ověřuje stejný `threadId` i `workspacePath`.

### `tests/codingWorker.test.ts`

- Přidán test, že `CodexSdkWorker.continueTask()` pokračuje existujícím threadem ve stejném workspace a předává konkrétní rework instrukci.

### `README.md`

- Dokumentován rework loop, limit pokusů, stejný Codex thread/worktree, artefakty `attempts/NN/`, `final-result.json` a ukončení při opakovaném nálezu nebo opakovaném `BLOCKED`.

## 5. Bezpečnostní stav po změně

Zachováno:

- Nebyl přidán Human Gate.
- Nebyl přidán commit cílového projektu, push, merge ani GitHub API.
- Nebyla přidána Memory, event log, Temporal, LangGraph ani UI.
- `danger-full-access` zůstává pouze explicitní kompatibilní režim a není automatický fallback.

Zlepšeno:

- Automatická oprava je ohraničená explicitním limitem.
- Rework instrukce je konkrétní a auditovatelná.
- Předchozí artefakty se nepřepisují; rework pokusy mají vlastní adresáře.
- Výsledný stav běhu je strojově čitelný přes `final-result.json`.
- Opakovaný stejný blocking finding ukončí automatiku místo dalšího slepého pokusu.

## 6. Známá rizika

- V tomto kontejneru nelze dokončit závislosti kvůli package firewallu a běží Node.js 20 místo požadovaného Node.js 22+, takže TypeScript/Vitest/build validace jsou blokované.
- Přesný název resume API v `@openai/codex-sdk` nebylo možné ověřit z nainstalovaných typů, protože dependency není v tomto prostředí dostupná; implementace podporuje `resumeThread` i `continueThread` bez lokálního `.d.ts` shimu.
- První pokus zůstává kvůli omezení rozsahu v root artefaktech runu; pouze rework pokusy jsou v `attempts/NN/`.

## 7. Doporučený další krok

V prostředí s Node.js 22+ a dostupnými dependencies spustit `npm ci` nebo `npm install`, poté `npm run typecheck`, `npm run test` a `npm run build`. Následně ověřit skutečný end-to-end Codex rework běh proti fixture projektu, zejména že SDK resume pokračuje existujícím threadem.
